## Bug #1 - 个人中心头像不显示

### 问题描述
点击个人中心，头像区域默认没有回显当前用户图像。

### 原因分析
`AvatarUpload` 组件的 `imageUrl` 初始化时使用了 `props.modelValue`，但 `userInfo.avatar` 在 `onMounted` 中才赋值，导致组件初始化时拿到空值，后续 watch 未能正确触发。

### 修复方案
在 `onMounted` 中赋值 `userInfo` 后，调用 `syncEditForm()` 同步数据，确保 `AvatarUpload` 的 `v-model` 绑定值在组件渲染时已更新。

### 修改文件
- `src/views/profile/index.vue`：新增 `syncEditForm()` 函数，在 `onMounted` 中调用同步数据

## Bug #2 - 个人信息表单不显示

### 问题描述
点击个人中心，基本信息区域表单默认没有回显完整信息，【昵称、邮箱、手机号】字段没有值回显，但点击【编辑】按钮后却自动回显了。

### 原因分析
表单的 `v-model` 绑定的是 `editForm`，而 `editForm` 只在点击"编辑"按钮（`toggleEdit`）时才从 `userInfo` 赋值。页面初始加载时 `editForm` 为空字符串，导致表单不显示数据。

### 修复方案
- 抽离 `syncEditForm()` 函数，将 `userInfo` 同步到 `editForm`
- 在 `onMounted` 初始化 `userInfo` 后立即调用 `syncEditForm()`
- 简化 `toggleEdit` 函数，复用同步逻辑

### 修改文件
- `src/views/profile/index.vue`

## Bug #3 - 左侧菜单偶尔不显示

### 问题描述
左侧菜单出现偶尔不显示的情况。

### 原因分析
在 `router/guards.ts` 中，`menuStore.fetchMenus()` 只在 `!userStore.userInfo` 条件下调用。如果用户信息从缓存恢复（`userInfo` 存在），但 `menus` 为空（如 `resetMenuState()` 清空了菜单），则菜单不会被加载。

**原逻辑**：
```ts
if (!userStore.userInfo) {
  await menuStore.fetchMenus()  // ← 只有 userInfo 不存在时才加载菜单
} else {
  next()  // ← userInfo 存在但 menus 为空时，菜单不加载
}
```

### 修复方案
分离用户信息初始化和菜单加载逻辑：
1. 先确保 `userInfo` 已初始化
2. 独立检查 `menuStore.menus.length === 0`，为空时始终重新加载
3. 菜单已存在则直接放行

### 修改文件
- `src/router/guards.ts`

## Bug #4 - 子菜单空白

### 问题描述
【系统设置】菜单展开后，子菜单显示为空白。

### 原因分析
CSS 选择器没有覆盖到嵌套子菜单项。Element Plus 的 `<el-sub-menu>` 内部会嵌套一个 `<el-menu>` 容器来渲染子菜单，其内部 `el-menu-item` 的文字颜色被 Element Plus 默认样式覆盖为白色，与背景色一致，导致看起来是空白。

**原选择器**：
```scss
.sidebar-menu {
  :deep(.el-menu-item),
  :deep(.el-sub-menu__title) {
    color: rgba(255, 255, 255, 0.65);
  }
}
```

### 修复方案
- 新增 `:deep(.el-sub-menu .el-menu-item)` 选择器，覆盖嵌套子菜单项的样式
- 新增 `:deep(.el-sub-menu .el-sub-menu__title):hover` 选择器，修复子菜单标题 hover 效果

### 修改文件
- `src/layouts/DefaultLayout.vue`
