# 迭代需求文档
## 文档信息
- **迭代版本**：V3.2
- **需求类型**：工程化迭代
- **涉及模块**：性能监控、错误上报、CI/CD、代码规范
- **后端依赖**：无

---

## 一、需求背景
完善项目工程化能力，建立性能监控、错误上报、代码规范检查、自动化构建流水线，确保项目可维护、可追踪、可追溯。

---

## 二、需求详情

### 1. 性能监控
1. **监控指标**
   - Web Vitals：LCP、FID、CLS、FCP
   - AI 特定指标：首字响应时间（TTFT）、Token/s、流式总耗时
2. **实现要求**
   - 使用 web-vitals 库收集核心指标
   - 自定义 AI 指标采集
   - 控制台可视化面板展示实时性能数据

### 2. 错误监控与上报
1. **监控范围**
   - JavaScript 运行时错误
   - 网络请求错误
   - AI 流式响应错误
   - 未捕获的 Promise 异常
2. **实现要求**
   - 全局错误捕获（window.onerror + unhandledrejection）
   - 错误上下文：用户操作、AI 请求参数、网络状态
   - 错误上报（可接入 Sentry 或自定义上报接口）
   - Mock 环境下本地记录

### 3. 代码规范与 CI/CD
1. **代码规范**
   - ESLint + Prettier 统一代码风格
   - Commitlint 规范提交信息
   - Husky + lint-staged Git Hooks
2. **CI/CD 流程**
   - 代码提交自动检查（lint + typecheck）
   - 构建产物优化（代码分割、Tree Shaking）
   - 构建分析（Bundle Analyzer）

---

## 三、非功能需求
- **性能**：监控代码不影响主流程性能
- **隐私**：错误上报不包含敏感数据
- **可配置**：监控开关、上报阈值可配置

---

## 四、验收标准
1. Web Vitals 指标正常采集
2. AI 特定指标（TTFT、Token/s）正确计算
3. 错误捕获与上报功能正常
4. ESLint、Prettier、Commitlint 集成完成
5. Git Hooks 自动检查生效

---

## 五、输出物
- 性能监控模块（utils/performance.ts）
- 错误监控模块（utils/error-monitor.ts）
- AI 指标采集组件
- 代码规范配置（eslint、prettier、commitlint）
- Husky + lint-staged 配置
- 依赖：web-vitals、@sentry/browser
