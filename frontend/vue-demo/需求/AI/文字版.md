# 具体学什么？三个月能上手的东西：
1. 流式消费
找一个支持SSE或分块响应的模型接口，前端用 fetch + ReadableStream 逐块解析，实现逐字打印效果，并且能中断生成。这个做完，面试至少能聊十分钟“背压”和“中断控制”。

2. 薄代理层
Node.js写一个十几行的BFF，把模型API的密钥藏在服务端，同时加一层简单的LRU缓存——相同请求直接返回历史结果。你只要说出“加了缓存，模型调用费降了四成”，面试官就会追问细节。

3. 浏览器端向量匹配
用 Transformers.js 跑一个轻量的嵌入模型，把历史对话或知识片段向量化后存进IndexedDB。用户新问题先本地算相似度，命中阈值才请求模型。这个本地检索+远程生成的做法，大多数前端没碰过，你做了就是亮点。

# 准备好被问：模型能直接生成界面，前端还有什么不可替代的价值?
不要扯虚的。直接说：
- 模型生成的HTML经常缺 alt、缺 aria 标签，需要前端自动补全；
- 模型返回的JSON可能多字段或少字段，前端要有防御性解析和兜底UI；
- 模型服务超时或报错时，前端必须靠本地模板 + 缓存数据撑住，不能让用户干等一个白屏。

## 1. 在前端实现一个Agent循环时，如何管理工具调用的异步执行、超时处理与结果合并？
场景：在"印客学院"的智能助教系统中，AI Agent需要按顺序调用多个工具（如计算器、天气查询、代码执行），并处理可能出现的超时和错误。

核心答案：设计一个基于状态机的Agent执行引擎，通过优先级队列管理工具调用，实现超时重试和错误降级机制，最后通过结果聚合器合并多个工具的输出。

### 实现思路
1. **任务调度器**：将Agent的思考过程分解为多个原子任务，每个工具调用作为独立任务。任务调度器负责管理任务队列，支持优先级调度（紧急任务优先）和依赖管理（任务B依赖任务A的结果）。
2. **异步执行管理器**：为每个工具调用创建Promise，设置超时时间（如30秒）。使用`Promise.race`实现超时控制，超时后取消请求并执行降级策略。
3. **错误处理链**
    - 一级重试：网络错误自动重试2次，使用指数退避策略
    - 二级降级：工具不可用时调用替代工具或使用本地近似计算
    - 三级跳过：非关键工具失败时跳过不影响主流程
    - 最终提示：所有尝试失败后向用户透明说明
4. **结果合并策略**
    - 时间窗口合并：在固定时间窗口内（如500ms）收集所有工具结果
    - 智能排序：按结果相关性、置信度、新鲜度排序
    - 冲突解决：不同工具结果冲突时，采用加权投票或请求用户确认
    - 渐进式展示：先展示部分结果，后补充完整结果
5. **执行状态可视化**：实时显示Agent思考过程，包括正在调用的工具、执行进度、预计剩余时间，增强用户对AI工作过程的理解。
