# 迭代需求文档
## 文档信息
- **迭代版本**：V3.1
- **需求类型**：核心功能迭代
- **涉及模块**：AI 本地向量检索、浏览器端推理、IndexedDB 存储
- **后端依赖**：无（完全浏览器端实现）

---

## 一、需求背景
实现浏览器端本地向量检索能力，使用 Transformers.js 运行轻量嵌入模型，将知识片段向量化存储到 IndexedDB。用户问题先在本地做相似度匹配，命中阈值才请求远程模型。这是大多数前端开发者未接触过的亮点能力。

---

## 二、需求详情

### 1. 本地向量检索
1. **功能范围**
   - 使用 Transformers.js 加载轻量嵌入模型（如 all-MiniLM-L6-v2）
   - 知识片段预计算向量并存入 IndexedDB
   - 用户问题实时计算向量，做余弦相似度匹配
2. **实现要求**
   - 模型首次加载显示进度提示
   - 向量计算使用 Web Worker 避免阻塞 UI
   - 相似度阈值可配置

### 2. IndexedDB 向量存储
1. **功能范围**
   - 设计 IndexedDB 结构存储向量数据
   - 支持向量 CRUD 操作
   - 数据版本管理与迁移
2. **实现要求**
   - 存储结构：id、文本内容、向量数组、元数据
   - 批量写入优化
   - 存储空间监控与清理

### 3. 本地检索 + 远程生成
1. **功能范围**
   - 用户提问 → 本地检索相似知识片段
   - 命中阈值：将检索结果作为上下文发送给 AI
   - 未命中阈值：直接发送问题给 AI
2. **实现要求**
   - RAG（检索增强生成）流程可视化
   - 显示检索到的相关片段
   - 支持手动切换"仅本地/远程/RAG"模式

---

## 三、非功能需求
- **性能**：向量计算在 Web Worker 中执行，不阻塞 UI
- **存储**：IndexedDB 存储容量合理，支持清理策略
- **兼容性**：浏览器不支持 Web Worker 时降级处理

---

## 四、验收标准
1. Transformers.js 模型正常加载并计算向量
2. IndexedDB 向量存储与检索功能正常
3. 本地检索命中时能正确返回相似片段
4. RAG 流程完整可用
5. 完全浏览器端实现，无需后端服务

---

## 五、输出物
- 向量检索模块（utils/vector-search.ts）
- IndexedDB 向量存储逻辑
- Web Worker 向量计算脚本
- RAG 流程管理
- 依赖：@xenova/transformers、idb
